Files

Reading from a File

Variables only live while your program is running. As soon as the program ends, everything stored in memory is gone. Files are how a program keeps information between runs and how it exchanges data with other programs: configuration files, logs, reports, data sets and so on.
Working with a file always follows the same three steps:
  1. Open the file with the built-in open() function. This gives you a file object.
  2. Read from it or write to it using the file object's methods.
  3. Close the file so the operating system can release it and any buffered data is actually saved to disk.
The examples in this section use a small text file called pi_digits.txt, saved in the same folder as the program. It contains the first 30 decimal places of pi spread over three lines: 
3.1415926535
  8979323846
  2643383279

Reading an Entire File

The open() function needs one argument: the name of the file you want to open. When you give it a plain file name, Python looks for the file in the current working directory, which is usually the folder you ran the program from (in an IDE like PyCharm, it is normally the project folder).
The with keyword creates a block that automatically closes the file when the block ends, even if an error happens inside it. You could call open() and close() yourself, but if your program crashes between the two calls the file is never closed, and if you close it too early you can no longer use it. Letting with handle it removes both problems.
The read() method returns the whole content of the file as a single string. 
with open('pi_digits.txt') as file_object:
    contents = file_object.read()

print(contents)
Output: 
3.1415926535
  8979323846
  2643383279
Notice the blank line at the end of the output. The file itself ends with a newline character (\n), so contents ends with one, and print() then adds its own newline. To remove whitespace (spaces, tabs and newlines) from the end of a string, use rstrip(): 
with open('pi_digits.txt') as file_object:
    contents = file_object.read()

print(contents.rstrip())
print(repr(contents[-3:]))  # '79\n'  the newline is really there
read() loads the whole file into memory at once. That is perfect for small and medium files, but for very large files (hundreds of megabytes) prefer reading line by line, as shown below.
From the next example on, we pass encoding='utf-8' to open(). The Encodings section explains why this is a good habit.

File Paths

Often the file you need is not next to your program. You then give open() a path instead of a bare file name. There are two kinds of paths:
  • Relative path: starts from the current working directory. For example 'text_files/notes.txt' means "the file notes.txt inside the folder text_files, which is inside the current directory". '../data.txt' means "one folder up".
  • Absolute path: the full location starting from the root of the drive, such as 'C:/Users/Amine/Documents/notes.txt' on Windows or '/home/amine/notes.txt' on Linux and macOS. It works no matter where the program is run from, but it ties your code to one machine.
Python accepts forward slashes (/) on every operating system, including Windows, so they are the safest choice in string paths. 
import os

os.makedirs('text_files', exist_ok=True)  # create the folder if it doesn't exist

# Relative path: the folder text_files inside the current working directory
with open('text_files/notes.txt', 'w', encoding='utf-8') as file:
    file.write('Notes stored in a subfolder.\n')

with open('text_files/notes.txt', encoding='utf-8') as file:
    print(file.read().rstrip())  # Notes stored in a subfolder.

print(os.getcwd())  # shows the current working directory relative paths start from
Be careful with backslashes in Windows paths. Inside a normal string, a backslash starts an escape sequence: \n is a newline and \t is a tab. The path below is silently corrupted: 
bad_path = 'C:\new_folder\table.txt'
print(bad_path)
# Output:
# C:
# ew_folder	able.txt

good_path = r'C:\new_folder\table.txt'   # raw string: backslashes are kept as-is
also_good = 'C:/new_folder/table.txt'    # forward slashes work on Windows too
print(good_path)  # C:\new_folder\table.txt
Use forward slashes, a raw string (r'...'), or better, the pathlib module described in its own section. Since Python 3.12, unknown escape sequences such as '\d' also produce a SyntaxWarning, which is a hint that you probably meant a raw string.

Reading Line by Line

A file object is iterable: looping over it with for gives you one line at a time. This is the most memory-friendly way to read a file, because Python only keeps the current line in memory, so it works even for files larger than your RAM.
Each line keeps its own newline character at the end, and print() adds another, which is why lines appear double spaced unless you strip them. 
filename = 'pi_digits.txt'

with open(filename, encoding='utf-8') as file_object:
    for line in file_object:
        print(line)
# Output (extra blank lines):
# 3.1415926535
#
#   8979323846
#
#   2643383279
#

with open(filename, encoding='utf-8') as file_object:
    for line in file_object:
        print(line.rstrip())
# Output:
# 3.1415926535
#   8979323846
#   2643383279
If you need line numbers, combine the loop with enumerate(): 
with open('pi_digits.txt', encoding='utf-8') as file_object:
    for number, line in enumerate(file_object, start=1):
        print(f"{number}: {line.strip()}")
# Output:
# 1: 3.1415926535
# 2: 8979323846
# 3: 2643383279

Making a List of Lines from a File

The file object is only usable inside the with block, because the file is closed when the block ends. If you want to work with the lines later, store them in a list first.
  • readlines() returns a list of lines, each still ending with \n.
  • read().splitlines() returns a list of lines without the newline characters, which is usually what you want.
with open('pi_digits.txt', encoding='utf-8') as file_object:
    lines = file_object.readlines()

print(lines)  # ['3.1415926535\n', '  8979323846\n', '  2643383279\n']

# The file is closed now, but the list is still available
pi_string = ''
for line in lines:
    pi_string += line.strip()

print(pi_string)       # 3.141592653589793238462643383279
print(len(pi_string))  # 32

# Everything read from a text file is a string; convert it to use it as a number
pi_value = float(pi_string)
print(pi_value)        # 3.141592653589793
Text files always give you strings. If a file contains numbers, convert them with int() or float() before doing arithmetic, otherwise '2' + '3' gives '23' instead of 5.

File Modes

The second argument of open() is the mode. It tells Python what you intend to do with the file. If you leave it out, the file is opened in read mode ('r').
Mode Meaning If the file exists If it does not exist
'r' Read (default) Opens it for reading FileNotFoundError
'w' Write Erases its contents first Creates it
'a' Append Adds new data at the end Creates it
'x' Exclusive creation FileExistsError Creates it
'r+' Read and write Opens it without erasing FileNotFoundError
'b' Binary (combined with another mode: 'rb', 'wb', 'ab') Reads and writes bytes instead of str; used for images, audio, zip files, etc.
Text mode ('t') is the default, so 'r' is the same as 'rt'. In text mode Python decodes bytes into characters and translates line endings; in binary mode you get the raw bytes untouched. 
# 'x' protects you from accidentally overwriting an existing file
with open('report.txt', 'w', encoding='utf-8') as file:
    file.write('First version\n')

try:
    with open('report.txt', 'x', encoding='utf-8') as file:
        file.write('Second version\n')
except FileExistsError:
    print('report.txt already exists, not overwriting it.')

# Binary mode returns bytes, not str
with open('pi_digits.txt', 'rb') as file:
    data = file.read(6)
print(data)        # b'3.1415'
print(type(data))  # <class 'bytes'>

Writing to a File

Writing to an Empty File

To write text, open the file in write mode ('w') and call the write() method with a string. If the file does not exist, Python creates it.
A few things to know about write():
  • It only accepts strings. To save a number, convert it first with str() or use an f-string.
  • It returns the number of characters written, which you can usually ignore.
  • The data may sit in a memory buffer until the file is closed, which is one more reason to use with.
filename = 'programming.txt'

with open(filename, 'w', encoding='utf-8') as file_object:
    file_object.write("I love programming.")

with open(filename, encoding='utf-8') as file_object:
    print(file_object.read())  # I love programming.

with open('numbers.txt', 'w', encoding='utf-8') as file_object:
    file_object.write(str(42))   # file_object.write(42) would raise TypeError
Opening an existing file in 'w' mode erases it immediately, before you write anything, and there is no undo. If you want to keep the old content, use append mode ('a'); if you want to make sure you never overwrite a file, use 'x'.

Writing Multiple Lines

Unlike print(), write() does not add a newline at the end of the text. If you call it several times without newlines, everything ends up on a single line. Add \n yourself wherever you want a line break.
To write a whole list of strings, use a loop or writelines(). Note that writelines() does not add newlines either, despite its name. 
filename = 'programming.txt'

with open(filename, 'w', encoding='utf-8') as file_object:
    file_object.write("I love programming.")
    file_object.write("I love creating new games.")

with open(filename, encoding='utf-8') as file_object:
    print(file_object.read())
# I love programming.I love creating new games.

with open(filename, 'w', encoding='utf-8') as file_object:
    file_object.write("I love programming.\n")
    file_object.write("I love creating new games.\n")

languages = ['Python', 'C', 'JavaScript']
with open('languages.txt', 'w', encoding='utf-8') as file_object:
    file_object.writelines(lang + '\n' for lang in languages)

with open('languages.txt', encoding='utf-8') as file_object:
    print(file_object.read().splitlines())  # ['Python', 'C', 'JavaScript']
print() can also write to a file through its file argument, and it adds the newline for you: print('Hello', file=file_object).

Appending to a File

Append mode ('a') keeps the existing content and adds everything you write at the end of the file. If the file does not exist yet, it is created. This is exactly what you want for logs, history files or anything that grows over time. 
filename = 'programming.txt'

with open(filename, 'a', encoding='utf-8') as file_object:
    file_object.write("I also love finding meaning in large datasets.\n")
    file_object.write("I love creating apps that can run in a browser.\n")

with open(filename, encoding='utf-8') as file_object:
    print(file_object.read().rstrip())
# Output:
# I love programming.
# I love creating new games.
# I also love finding meaning in large datasets.
# I love creating apps that can run in a browser.

Working with Multiple Files

Looping Over a List of Files

Once the logic for one file lives in a function, handling many files is just a loop. The function below counts the words in a file. If one of the files is missing, it reports the problem and moves on instead of stopping the whole program (see the Exceptions chapter for try/except). 
def count_words(filename):
    """Count the approximate number of words in a file."""
    try:
        with open(filename, encoding='utf-8') as f:
            contents = f.read()
    except FileNotFoundError:
        print(f"Sorry, the file {filename} does not exist.")
    else:
        num_words = len(contents.split())
        print(f"The file {filename} has about {num_words} words.")

# Create two sample files to work with
with open('story.txt', 'w', encoding='utf-8') as f:
    f.write("Once upon a time there was a curious programmer.\n")
with open('poem.txt', 'w', encoding='utf-8') as f:
    f.write("Roses are red\nViolets are blue\n")

filenames = ['story.txt', 'missing.txt', 'poem.txt']
for filename in filenames:
    count_words(filename)
# Output:
# The file story.txt has about 9 words.
# Sorry, the file missing.txt does not exist.
# The file poem.txt has about 6 words.

Opening Several Files at Once

A single with statement can open several files. This is handy for copying or transforming data from one file into another. Reading and writing line by line keeps memory usage low no matter how large the source file is. Since Python 3.10 you can wrap the list of files in parentheses to spread it over several lines. 
# Copy pi_digits.txt into a new file, removing the indentation
with (
    open('pi_digits.txt', encoding='utf-8') as source,
    open('pi_clean.txt', 'w', encoding='utf-8') as destination,
):
    for line in source:
        destination.write(line.strip() + '\n')

with open('pi_clean.txt', encoding='utf-8') as f:
    print(f.read().splitlines())  # ['3.1415926535', '8979323846', '2643383279']

Merging Files

To combine files, open the output once and append the contents of each input file to it. Opening the output in 'w' mode outside the loop means it is emptied only once, at the start. 
sources = ['story.txt', 'poem.txt']

with open('combined.txt', 'w', encoding='utf-8') as output:
    for name in sources:
        with open(name, encoding='utf-8') as source:
            output.write(f"--- {name} ---\n")
            output.write(source.read())

with open('combined.txt', encoding='utf-8') as f:
    print(f.read().rstrip())
# Output:
# --- story.txt ---
# Once upon a time there was a curious programmer.
# --- poem.txt ---
# Roses are red
# Violets are blue

Working with Paths using pathlib

The standard library module pathlib represents paths as Path objects instead of plain strings. This is the modern, recommended way to work with paths:
  • You join paths with the / operator, and Python uses the correct separator for the operating system.
  • Useful information is available as attributes: name, stem, suffix, parent.
  • Common tasks are one method call: exists(), read_text(), write_text(), mkdir(), glob().
Every function that accepts a path string, including open(), also accepts a Path object. 
from pathlib import Path

path = Path('text_files') / 'notes.txt'   # the / operator joins path parts
print(path.name)     # notes.txt
print(path.stem)     # notes
print(path.suffix)   # .txt
print(path.parent)   # text_files
print(path.exists()) # True (we created it earlier)

print(Path.cwd())    # the current working directory (an absolute path)
print(path.resolve().is_absolute())  # True: resolve() turns it into an absolute path

Reading and Writing with Path

read_text() opens the file, reads everything, and closes it for you in one call. write_text() does the same for writing; like 'w' mode, it replaces any existing content. These are perfect for small files. 
from pathlib import Path

path = Path('pi_digits.txt')
contents = path.read_text(encoding='utf-8')
lines = contents.splitlines()
pi_string = ''.join(line.strip() for line in lines)
print(pi_string)  # 3.141592653589793238462643383279

output = Path('reports') / '2024' / 'summary.txt'
output.parent.mkdir(parents=True, exist_ok=True)  # create reports/2024 if needed
output.write_text('All tests passed.\n', encoding='utf-8')
print(output.read_text(encoding='utf-8').rstrip())  # All tests passed.

# Path objects work with open() as well
with open(output, 'a', encoding='utf-8') as f:
    f.write('Report generated automatically.\n')

Listing Files in a Folder

iterdir() yields everything directly inside a folder, and glob() yields the paths that match a pattern. rglob() searches subfolders too. They return generators, so wrap them in sorted() or list() if you need a list. 
from pathlib import Path

folder = Path('.')
text_files = sorted(folder.glob('*.txt'))
for file in text_files[:3]:
    print(file.name, file.stat().st_size, 'bytes')

print([p.as_posix() for p in Path('reports').rglob('*.txt')])  # ['reports/2024/summary.txt']

# Delete a file (missing_ok avoids an error if it is already gone)
Path('numbers.txt').unlink(missing_ok=True)

Encodings

On disk, a file is just a sequence of bytes. An encoding is the rule that maps characters to bytes and back. Plain English letters are encoded the same way by almost every encoding, which is why problems often stay hidden until a file contains an accented letter, an emoji, or Arabic or Chinese text.
When you do not pass encoding, open() uses your system's default, which depends on the operating system and its settings: usually UTF-8 on Linux and macOS, but often cp1252 on Windows. A file written on one machine can then be unreadable or garbled on another.
UTF-8 can represent every character and is the standard on the web, so always pass encoding='utf-8' when opening text files. (Python 3.15 is planned to make UTF-8 the default, but explicit is still better than implicit.) 
text = 'Café ☕ مرحبا'

with open('greeting.txt', 'w', encoding='utf-8') as f:
    f.write(text)

with open('greeting.txt', encoding='utf-8') as f:
    print(f.read())  # Café ☕ مرحبا

print(len(text))                  # 12 characters
print(len(text.encode('utf-8')))  # 20 bytes: non-ASCII characters take 2 to 4 bytes each

What Goes Wrong with the Wrong Encoding

Reading a file with a different encoding from the one it was written with either produces garbled text (called mojibake) or raises a UnicodeDecodeError. The errors argument lets you choose what happens with bytes that cannot be decoded: 'strict' (the default, raise an error), 'replace' (insert �) or 'ignore' (drop them). 
with open('cafe.txt', 'w', encoding='utf-8') as f:
    f.write('café')

# UTF-8 bytes read as Latin-1: garbled but no error
with open('cafe.txt', encoding='latin-1') as f:
    print(f.read())  # cafÃ©

# Latin-1 bytes read as UTF-8: error
with open('cafe_latin1.txt', 'w', encoding='latin-1') as f:
    f.write('café')

try:
    with open('cafe_latin1.txt', encoding='utf-8') as f:
        print(f.read())
except UnicodeDecodeError as e:
    print('Error:', e)
# Error: 'utf-8' codec can't decode byte 0xe9 in position 3: unexpected end of data

with open('cafe_latin1.txt', encoding='utf-8', errors='replace') as f:
    print(f.read())  # caf�
Files saved by Excel or Notepad on Windows sometimes start with an invisible "byte order mark". Opening them with encoding='utf-8-sig' removes it automatically.

Storing Data with JSON

Writing plain text is fine for notes and logs, but structured data such as lists and dictionaries would have to be converted to text by hand and parsed back later. The json module does this for you. JSON (JavaScript Object Notation) is a simple text format understood by practically every programming language, which makes it the usual choice for saving settings and exchanging data with web services.
  • json.dump(data, file) writes a Python object to an open file.
  • json.load(file) reads it back and returns the Python object.
  • json.dumps(data) and json.loads(text) (with an s for "string") do the same with strings instead of files.
import json

numbers = [2, 3, 5, 7, 11, 13]

with open('numbers.json', 'w', encoding='utf-8') as f:
    json.dump(numbers, f)

with open('numbers.json', encoding='utf-8') as f:
    loaded = json.load(f)

print(loaded)        # [2, 3, 5, 7, 11, 13]
print(type(loaded))  # <class 'list'>  a real list, not a string
With indent, the output is formatted to be readable by humans: 
import json

student = {'name': 'Sara', 'age': 21, 'courses': ['Math', 'Physics'], 'graduated': False}
print(json.dumps(student, indent=4))
# Output:
# {
#     "name": "Sara",
#     "age": 21,
#     "courses": [
#         "Math",
#         "Physics"
#     ],
#     "graduated": false
# }
JSON has fewer types than Python, so some values change on the round trip: tuples come back as lists, dictionary keys always become strings ({1: 'a'} comes back as {'1': 'a'}), and sets, dates and custom objects cannot be saved at all without converting them first (you get a TypeError). True, False and None become true, false and null in the file.

Example: Remembering the User

Here is a small program that asks for the user's name the first time it runs, saves it, and greets the user by name on every later run. It is split into functions that each do one job, which makes the program easier to read and to change. get_stored_username() returns None when no name has been saved yet, and the caller reacts to that. 
import json
from pathlib import Path

def get_stored_username(path):
    """Return the stored username if available, otherwise None."""
    if path.exists():
        contents = path.read_text(encoding='utf-8')
        return json.loads(contents)
    return None

def get_new_username(path):
    """Ask for a new username and save it."""
    username = input("What is your name? ")
    path.write_text(json.dumps(username), encoding='utf-8')
    return username

def greet_user():
    """Greet the user by name."""
    path = Path('username.json')
    username = get_stored_username(path)
    if username:
        print(f"Welcome back, {username}!")
    else:
        username = get_new_username(path)
        print(f"We'll remember you when you come back, {username}!")

greet_user()
# First run:
# What is your name? Amine
# We'll remember you when you come back, Amine!
# Second run:
# Welcome back, Amine!
If the JSON file can be edited by hand, it may end up corrupted. Wrapping json.loads() in try/except json.JSONDecodeError lets the program fall back to asking for the name again instead of crashing.

CSV Files

CSV (Comma-Separated Values) is the simplest format for tables: one row per line, with the values separated by commas, and usually a first line holding the column names. Spreadsheets like Excel can open and save CSV files.
Splitting each line on commas yourself breaks as soon as a value contains a comma, such as "Paris, France". The csv module handles quoting and these edge cases correctly.

Writing with csv.writer

Create a writer from an open file, then call writerow() for one row or writerows() for many. Each row is a list of values; non-string values are converted to strings automatically.
Always open CSV files with newline=''. The csv module writes its own line endings, and without this argument Windows would add an extra carriage return, producing a blank line between every row. 
import csv

rows = [
    ['name', 'city', 'score'],
    ['Amine', 'Paris, France', 92],
    ['Sara', 'Algiers', 85],
    ['Omar', 'Tunis', 78],
]

with open('scores.csv', 'w', newline='', encoding='utf-8') as f:
    writer = csv.writer(f)
    writer.writerows(rows)

with open('scores.csv', encoding='utf-8') as f:
    print(f.read().rstrip())
# Output:
# name,city,score
# Amine,"Paris, France",92
# Sara,Algiers,85
# Omar,Tunis,78

Reading with csv.reader

csv.reader yields each row as a list of strings. Use next() to consume the header row before looping over the data. 
import csv

with open('scores.csv', newline='', encoding='utf-8') as f:
    reader = csv.reader(f)
    header = next(reader)          # the first row: column names
    print(header)                  # ['name', 'city', 'score']
    total = 0
    for row in reader:
        print(row)
        total += int(row[2])       # values are strings: convert before adding
# ['Amine', 'Paris, France', '92']
# ['Sara', 'Algiers', '85']
# ['Omar', 'Tunis', '78']

print('Total:', total)             # Total: 255

Reading with csv.DictReader

csv.DictReader uses the header row as keys and gives you each row as a dictionary. Code like row['score'] is much easier to read than row[2], and it keeps working if someone reorders the columns. 
import csv

with open('scores.csv', newline='', encoding='utf-8') as f:
    reader = csv.DictReader(f)
    for row in reader:
        print(f"{row['name']} from {row['city']} scored {row['score']}")
# Amine from Paris, France scored 92
# Sara from Algiers scored 85
# Omar from Tunis scored 78

Writing with csv.DictWriter

The matching csv.DictWriter writes dictionaries. You list the column names in fieldnames and call writeheader() once before writing the rows. 
import csv

students = [
    {'name': 'Lina', 'grade': 17},
    {'name': 'Yacine', 'grade': 14},
]

with open('grades.csv', 'w', newline='', encoding='utf-8') as f:
    writer = csv.DictWriter(f, fieldnames=['name', 'grade'])
    writer.writeheader()
    writer.writerows(students)

with open('grades.csv', encoding='utf-8') as f:
    print(f.read().splitlines())  # ['name,grade', 'Lina,17', 'Yacine,14']
Things to Remember
  • Use with open(...) so files are always closed, even after an error.
  • Pass encoding='utf-8' for text files, and newline='' for CSV files.
  • 'w' erases the file immediately; use 'a' to add to it and 'x' to refuse to overwrite it.
  • Everything read from a text or CSV file is a string; convert numbers explicitly.
  • Prefer pathlib.Path over string paths, and json or csv over hand-made formats.
